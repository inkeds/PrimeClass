# 优学课堂 AI 设计协作文档

## 1. 文档定位

- 文档版本：v1.0
- 更新时间：2026-04-02
- 适用对象：需要继续设计或重构本项目前台 / 后台 UI 的其他 AI 工具、设计师、前端工程师
- 文档目标：让新的 AI 在不反复追问上下文的情况下，快速理解项目的业务边界、页面结构、真实已实现功能、UI 约束和不可随意改动的规则

这不是一份单纯的视觉规范文档，而是一份“设计交接 + 功能语义 + 页面边界 + 技术落点”的综合说明。

## 2. 项目一句话说明

优学课堂是一个面向高中学习场景的网课系统，包含学员端移动端风格前台和后台管理系统，核心围绕“同步课 + 专题课 + 学习库 + 个人中心 + 激活码会员体系 + 内容运营后台”展开。

## 3. 当前项目快照

### 3.1 技术栈

- 学员端前台：Next.js 16 + React 19 + TypeScript
- 后台管理端：Next.js 16，同一前端工程下的 `/admin`
- 后端 API：Node.js + TypeScript + Fastify
- 数据库：MySQL 8
- 文件存储：`local`、`s3`、`tencent_cos`、`ftp`

### 3.2 仓库结构

```text
<project-root>
├── app-web    # 统一前端工程，学员端 + 后台端
├── server     # Fastify API
├── docs       # 设计、接口、数据库、部署文档
└── deploy     # PM2 / Nginx 部署示例
```

### 3.3 访问入口

- 学员端首页：`/`
- 学员端登录：`/login`
- 学员端专题课：`/topics`
- 学员端学习库：`/library`
- 学员端我的：`/me`
- 学员端课程详情：`/courses/[courseId]`
- 学员端课时播放：`/lessons/[lessonId]?courseId=xxx`
- 学员端学科专属页：`/subjects/[subjectCode]`
- 后台登录：`/admin/login`
- 后台工作台：`/admin`

### 3.4 API 前缀

- 学员端 API：`/api/v1/app`
- 后台 API：`/api/v1/admin`

### 4.1 明确已做

- 用户登录、会话与个人中心
- 同步课、专题课、课程详情、课时播放
- 课程收藏、学习进度、笔记
- 首页版本 / 年级筛选
- 学科专属页
- 专题标签与专题课筛选
- 学习库
- 前台站内通知查看
- 前台设置中的通知开关
- 后台课程管理
- 后台章节 / 课时管理
- 后台用户管理
- 后台会员套餐管理
- 后台激活码批次、激活码列表、兑换记录
- 后台内容维度

- 第三方充值
- 支付订单
- 退款
- 多租户

### 4.3 会员体系边界

- 当前会员体系只支持激活码
- 不做微信支付、支付宝支付、苹果支付等第三方充值
- 会员状态核心分为：普通、有效会员、过期会员、永久会员
- 激活码可叠加时长
- 永久会员不应继续显示强运营式 VIP 引导

## 5. 设计基准与视觉方向

### 5.1 前台设计基准

- 主要参考：`docs/demo.html`
- 风格关键词：轻、白、浅灰、学习蓝、少量 VIP 金
- 端形态：移动端优先，像 H5 / App 页面，不是传统 PC 页面
- 页面氛围：大面积浅背景 + 白色卡片 + 小面积高亮
- 卡片圆角：中小圆角为主，不能过度夸张
- 文案风格：简洁，避免重复副标题和过多解释性段落

### 5.2 后台设计基准

- 后台是全屏响应式系统，不是手机样机
- 左侧固定导航 + 顶部操作区 + 内容主区
- 风格统一、平整、轻量、偏运营后台
- 所有列表、筛选、按钮、表单需要统一样式，不允许每页一套风格
- 圆角按钮、标签、卡片应统一，不要同模块里出现多套尺寸

### 5.3 视觉禁区

- 不要突然引入深色后台主风格
- 不要把前台改成复杂运营落地页
- 不要把后台做成强拟物、超大圆角、强渐变卡片堆叠的样式
- 不要给简单弹窗加很多副标题、辅助文案、无意义装饰
- 不要把同一类功能在多个页面重复做两个入口

## 6. 核心业务模型

### 6.1 内容主结构

项目里的内容主结构不是“通用字典”，而是“内容维度”。

内容维度包括：

- 教材版本 `version`
- 学科 `subject`
- 年级 `grade`
- 学期 `term`

它们负责前台内容分发和课程筛选主链路。

### 6.2 内容维度的职责分工

- 教材版本：决定整站当前内容范围，是最上层入口
- 学科：决定首页图标导航和学科专属页入口
- 年级：是第二层筛选，已被放进首页右上角筛选器中
- 学期：更细的课程区分层，不是首页一级入口

### 6.3 通用字典的职责

通用字典只负责辅助枚举，不负责站点主结构。

适合放在通用字典的内容：

- 推荐标签 `recommend_tag`
- 展示样式枚举
- 辅助状态标签
- 轻量配置型选项

不应该放在通用字典的内容：

- 学科
- 教材版本
- 年级
- 学期

### 6.4 推荐标签

已接入课程业务，采用字典类型 `recommend_tag`。

推荐标签的作用：

- 后台课程编辑时可选择
- 前台课程卡显示推荐角标
- 前台课程详情页显示推荐角标
- 收藏列表、首页同步课等场景也会透出推荐标签

### 6.5 课程结构

课程有两类：

- 同步课 `sync`
- 专题课 `topic`

课程结构支持多级目录：

- 章节 `chapter`
- 小节 `section`
- 课时 `lesson`

规则：

- 课程基础信息编辑和章节 / 课时管理已拆开
- 章节 / 课时不放在课程编辑表单里维护
- 在课程列表中进入单独的“章节课时管理”弹窗
- 课时顺序通过上移 / 下移调整，不靠用户手工输入排序权重
- 已发布课时也支持删除
- 课时状态支持切换：`draft` / `published` / `offline`

### 6.6 资源与封面

- 所有媒体、讲义、封面都走资源上传
- 课程封面在后台课程编辑页单独上传
- 课时媒体文件在章节 / 课时管理中上传
- 上传时使用当前默认存储方式
- 前台课程卡、课程详情页、首页推荐优先使用课程封面

## 8. 学员端页面说明

### 8.1 登录页 `/login`

作用：

- 学员账号登录
- 登录成功后跳转原目标页面或首页

设计要求：

- 简单，不要过多营销区块
- 明确登录态切换结果

### 8.2 首页 `/`

作用：

- 学员端主分发页
- 当前以同步课分发为核心

页面结构：

1. 顶部栏
2. 教材版本 + 年级组合筛选触发器
3. 会员状态胶囊
4. 搜索按钮
5. 站内通知按钮
6. Banner
7. 学科导航图标区
8. 继续学习或登录提示区
9. 同步精讲课程列表
10. 大家都在学 / 热门课程区
11. 右下角激活码兑换浮动按钮

关键交互：

- 顶部右上角筛选器同时控制教材版本与年级
- 版本 / 年级状态会持久化到本地 `localStorage`
- 学科图标点击后进入独立学科页，而不是在首页内切换
- 搜索以弹层方式打开，结果直接列表展示
- 搜索是课程搜索，不应做成白页上永久占位的大输入框
- 站内通知从首页右上角铃铛进入
- 登录后首页应该显示真实会员状态和学习信息
- 永久会员 / 已开通会员不应继续展示强引导式“激活 VIP 后解锁”文案

当前重要规则：

- 首页左上角筛选不是“学科”，而是“教材版本 + 年级”
- 年级不再单独作为首页内容区的大块筛选条
- 顶部筛选在切页后应保持

### 8.3 学科专属页 `/subjects/[subjectCode]`

作用：

- 某一学科下的同步课专属页

页面结构：

1. 返回按钮
2. 右上角教材版本 + 年级筛选触发器
3. 学科 Hero 卡
4. 当前学科课程列表

重要规则：

- 学科页继承首页的教材版本 / 年级状态
- 学科页不需要再在内容区下面单独做一组“年级筛选”
- 学科页头部副标题应尽量克制，避免重复说明
- 页面要比首页更聚焦，不应塞入过多运营模块

### 8.4 专题课页 `/topics`

作用：

- 展示专题课和专题标签

页面结构：

1. 顶部教材版本选择
2. 学科筛选
3. 专题标签筛选
4. 专题课列表

规则：

- 专题课与同步课视觉上应有区分
- 专题标签用于强化“提分 / 方法 / 重难点 / 专题训练”的感知
- 专题标签的后台管理在课程管理里独立维护

### 8.5 课程详情页 `/courses/[courseId]`

作用：

- 展示课程封面、简介、教师、推荐标签、目录
- 提供收藏与进入课时的入口

页面内容：

- 封面
- 课程标题与简介
- 教师 / 学科 / 年级 / 学期 / 版本信息
- 推荐标签角标
- 收藏状态
- 章节目录

规则：

- 课程封面优先使用后台上传图片
- 收藏不应出现重复入口造成认知冲突
- 推荐标签应作为轻量角标，不要抢过课程主信息

### 8.6 课时播放页 `/lessons/[lessonId]`

作用：

- 播放视频或音频
- 展示讲义下载、笔记、收藏
- 记录学习进度

播放态说明：

- 媒体支持视频与音频
- 支持 VIP 限制和试看
- 不可访问时展示锁定态
- 锁定态不能遮挡播放器主体到不可理解的程度

交互：

- 可收藏课程
- 可保存笔记
- 可继续学习
- 受会员状态和试看开关影响

### 8.7 学习库 `/library`

作用：

- 聚合个人学习资产

页面内容：

- 历史数量
- 下载数量
- 收藏数量
- 笔记数量
- 继续学习列表
- 我的收藏列表
- 最近笔记列表

设计要求：

- 工具页风格，比首页更克制
- 强调“回到正在学的内容”
- 学习记录卡要对齐、统一，不要视觉松散

### 8.8 我的 `/me`

作用：

- 承载账号、会员、通知、帮助文档、设置

当前菜单结构：

- 账号与安全
- 消息通知
- 在线知识文档
- 设置
- 退出登录

规则：

- “帮助与在线客服”已改为“在线知识文档”
- “通知开关”放在“设置”页里，不放在“消息通知”页里
- “消息通知”页只放具体通知内容
- “设置”在我的页面菜单中放在更靠下位置
- 当前账号安全先只考虑邮箱

具体弹层：

- 账号与安全：编辑邮箱
- 设置：编辑通知开关
- 消息通知：查看后台发布的通知
- 在线知识文档：本地知识文档列表 + 搜索

## 10. 后台页面说明

### 10.1 工作台 `/admin`

作用：

- 运营总览
- 最新内容和用户动态观察

当前模块：

- 核心指标卡
- 年级 / 教材版本热度切换图
- 最新同步课程上线
- 最新学员

重要规则：

- “核心运营指标分布卡片”现在主要用于观察年级或教材版本热度
- 不要做成泛泛的装饰图表

### 10.2 课程管理 `/admin/courses`

内部标签：

- 课程列表
- 专题标签
- 资源管理

#### 课程列表

支持：

- 新增课程
- 编辑课程
- 上架 / 下架 / 删除
- 进入章节课时管理
- 上传课程封面
- 设置推荐标签

课程编辑表单应只做：

- 标题
- 课程类型
- 学科 / 年级 / 学期 / 教材版本
- 教师
- 访问权限
- 课程状态
- 推荐标签
- 封面上传
- 课程简介
- 少量高级设置

不应做：

- 在课程编辑页里直接维护章节、课时、媒体上传
- 过度复杂的长表单

#### 章节课时管理

这是课程管理里的关键二级操作，不应回收进课程编辑表单。

支持：

- 查看当前课程的树形章节列表
- 新增章节 / 小节 / 课时
- 设置节点状态
- 上传音频 / MP4
- 上传讲义
- 设置课时时长
- 设置权限
- 设置试看
- 上移 / 下移调整顺序
- 删除已发布或未发布节点

规则：

- 节点状态支持：草稿 / 已发布 / 已下架
- 顺序通过操作按钮维护
- 不再要求手输排序权重
- 媒体文件走当前默认存储

#### 专题标签

作用：

- 为专题课提供归类标签

要求：

- 标签维护独立，不混入课程基础表单
- 课程编辑中选择专题标签时应使用统一的矩形 / 卡片式多选样式

#### 资源管理

作用：

- 查看已上传资源
- 为课程封面、课时媒体、讲义文件提供复用基础

### 10.3 内容维度 `/admin/content-dimensions`

作用：

- 管理前台内容主结构

维度类型：

- 教材版本
- 学科
- 年级
- 学期

设计重点：

- 要明确表现“结构分工”
- 突出内容维度与通用字典是两套不同能力
- 需要体现版本、学科、年级、学期之间的关联关系

页面要传达的认知：

- 教材版本决定整站内容范围
- 学科决定首页导航入口
- 年级负责第二层课程区分
- 学期只是更细的内容区分

### 10.4 学员列表 `/admin/users`

作用：

- 学员账号、会员、学习行为、客服备注管理

支持：

- 查看用户列表
- 查看详情
- 冻结 / 恢复状态
- 查看学习记录
- 录入客服备注

详情内容：

- 基本资料
- 内容偏好
- 学习记录
- 客服备注

### 10.5 会员管理 `/admin/membership`

内部标签：

- 会员套餐
- 激活码批次
- 激活码列表
- 兑换记录

#### 会员套餐

支持：

- 新增 / 编辑套餐
- 卡类型
- 卡色调
- 时长
- 永久会员
- 权益说明
- 启停状态

#### 激活码批次

支持：

- 创建批次
- 批量生成激活码
- 设置有效期
- 设置渠道来源
- 导出批次

#### 激活码列表

支持：

- 查看单码状态
- 查看所属批次
- 查看使用人
- 作废激活码

#### 兑换记录

支持：

- 查看兑换成功 / 失败
- 查看失败原因
- 查看对应套餐和账号

设计要求：

- 切换标签时，布局不要变形或左右抖动
- 会员管理内部按钮、标签、表格圆角风格需统一

### 10.6 通用字典 `/admin/dictionaries`

作用：

- 维护非主结构类枚举

适合维护：

- 推荐标签
- 展示风格
- 辅助状态

页面必须明确告诉使用者：

- 核心维度去“内容维度”
- 通用字典不负责首页版本切换和学科导航

### 10.7 通知发布 `/admin/notifications`

说明：

- 这是系统设置中的通知能力抽出的独立入口
- 当前路由会直接进入系统设置页的 `notifications` 标签

支持：

- 新建通知
- 编辑通知
- 通知语气 `tone`
- 状态 `draft / published / disabled`
- 前台可见内容维护

通知流向：

- 后台发布通知
- 前台首页站内通知弹层可查看
- 前台“我的 > 消息通知”也能查看

### 10.8 系统管理 `/admin/settings`

内部标签：

- 基础设置
- 展示设置
- 上传设置
- 存储设置

#### 基础设置

偏系统级参数，如站点基本信息。

#### 展示设置

偏前台显示文案，如 VIP 引导文案、默认展示配置等。

#### 上传设置

偏上传限制和上传行为。

#### 存储设置

支持配置四种存储：

- 本地存储 `local`
- S3 存储桶 `s3`
- 腾讯云 COS `tencent_cos`
- FTP 存储 `ftp`

当前交互原则：

- 存储配置是“添加 / 编辑某个存储提供方”，不是把所有配置硬塞一个大表单
- 可以启用 / 禁用
- 可设置默认存储
- 当前默认存储直接影响课程封面、课时媒体、讲义上传

## 12. 关键业务规则

### 12.1 首页筛选规则

- 首页顶部筛选是“教材版本 + 年级”
- 筛选状态会持久化
- 切换页面后返回首页应保留
- 学科页继承这组筛选

### 12.2 学科页规则

- 学科图标从首页跳转进入
- 学科页不再重复做页面内年级筛选块
- 只保留右上角组合筛选

### 12.3 会员显示规则

- 已登录且已开通会员时，前台不应再显示强烈的“去激活 VIP”引导
- 永久会员应使用明确的已生效状态
- 会员色调可以跟套餐色调有关，但前台要保持可读性，避免灰底灰字不可辨

### 12.4 通知规则

- 前台“消息通知”只展示通知内容，不负责管理开关
- 通知开关在“设置”中维护
- 后台必须有通知发布入口

### 12.5 课程封面规则

- 前台课程卡、详情页、首页课程区优先使用后台配置的课程封面
- 课程创建和编辑都要有封面上传能力

### 12.6 上传规则

- 后台上传课程媒体主要是音频和 MP4
- 讲义是附件型资源
- 上传需要连通当前已配置的默认存储
- 不要做“傻瓜式一次性乱序上传”交互

### 12.7 树形目录规则

- 章节 / 小节 / 课时需要有清晰层级
- 需要支持父级挂载
- 需要支持顺序调整
- 状态切换应即时生效

## 13. UI 设计时不要破坏的共识

### 13.1 前台

- 移动端布局优先
- 首页顶部筛选与通知是核心，不要弱化到看不见
- 学科图标是跳转，不是首页内联筛选
- 搜索弹层要简洁，不要塞太多副标题
- 学科页比首页更简洁
- 学习库偏工具属性，少营销
- 我的页优先体现账号、会员、设置、通知、知识文档

### 13.2 后台

- 一套统一的后台视觉，不允许每页单独起风格
- 左右不应有莫名留白边框感
- 列表页、弹窗、表单、标签、按钮圆角统一
- 切页或切 Tab 时不应出现明显变形 / 抖动 / 宽度跳动
- 表单尽量短、直白、按任务拆分
- 不要把“课程编辑”和“章节上传”重新揉回一张大表单

## 16. 结论

对其他 AI 来说，这个项目最容易误判的不是“有没有页面”，而是“哪些配置属于主结构，哪些只是辅助枚举；哪些操作应该拆页，哪些不能合并；哪些运营引导在会员态下必须收敛”。  
继续设计时，务必先守住业务边界、筛选逻辑、会员规则和后台操作逻辑，再去做视觉升级。
