## 1. 文档信息

- 文档版本：v0.2
- 更新时间：2026-03-23
- 原型依据：`docs/demo.html`
- 适用范围：移动端 App / H5 首版界面设计、后台管理系统设计与项目实施规划
- 文档目标：基于现有高保真原型，沉淀统一的产品视觉、后台模块、业务规则、交互规范和实施节奏，作为后续 UI 设计、前后端开发、联调和验收的共同基线

## 2. 项目定位

### 2.1 产品概述

优学课堂是一款面向高中阶段用户的移动端课程学习产品，围绕“同步课 + 专题课 + 学习库 + 个人权益中心”构建完整学习闭环。当前原型重点突出两个核心价值：

1. 低门槛获取同步课程内容，支持按教材版本、学科、章节快速进入学习。
2. 通过 VIP 激活码兑换形成权益感知，强化“全站免费学”的运营转化路径。

### 2.2 目标用户

- 高中学生：以课内同步学习、查漏补缺、专题提分为主。
- 家长辅助决策人群：关注课程是否系统、是否免费、是否方便持续学习。

### 2.3 设计关键词

- 清晰
- 轻量
- 提分导向
- 权益感
- 可信赖
- 移动端优先

### 2.4 核心业务目标

- 提高同步课程内容曝光与点击转化。
- 强化“继续学习”路径，缩短用户再次开课的操作链路。
- 提升 VIP 激活码兑换入口的触达率与转化率。
- 通过学习库和个人页沉淀学习资产与账号关系。

## 3. 信息架构

### 3.1 一级架构

产品采用底部 Tab 导航，共 4 个一级页面：

| Tab | 页面名称 | 主要目标 |
| --- | --- | --- |
| 01 | 同步课 | 找课、选版本、按学科浏览、继续学习 |
| 02 | 专题课 | 针对重难点场景进行提分学习 |
| 03 | 学习库 | 查看历史、下载、收藏、笔记与学习进度 |
| 04 | 我的 | 账号、消息、客服、VIP 兑换、退出登录 |

### 3.2 全局浮层

除一级页面外，原型中还包含 3 个全局层级组件：

| 组件 | 作用 | 触发位置 |
| --- | --- | --- |
| 激活码兑换弹窗 | 输入并兑换 VIP 激活码 | 首页浮动按钮、我的页兑换卡 |
| 播放器预览页 | 课程播放与课件功能入口 | 课程卡、继续学习卡、专题卡 |
| Toast 提示 | 反馈兑换成功、版本列表加载等轻提示 | 全局 |

### 3.3 关键用户路径

#### 路径 A：同步学习

1. 进入首页。
2. 选择教材版本。
3. 搜索或按学科浏览。
4. 点击课程卡。
5. 进入播放器。
6. 下载讲义或记录笔记。

#### 路径 B：继续学习

1. 进入首页或学习库。
2. 点击“继续”按钮或继续学习卡。
3. 直接拉起播放器。

#### 路径 C：VIP 兑换

1. 通过首页悬浮兑换按钮或个人页 VIP 卡进入兑换弹窗。
2. 输入 12 位激活码。
3. 点击激活。
4. 显示成功 Toast。
5. 关闭弹窗并回到原页面。

## 4. 页面设计规范

### 4.1 同步课首页

#### 页面目标

- 承担课程分发首页职责。
- 提供版本切换、搜索、课程推荐和继续学习入口。
- 兼顾 VIP 权益曝光。

#### 页面结构

1. 顶部区：教材版本选择器、VIP 标签、搜索框、日历提醒图标。
2. Banner 区：同步视频课程主题视觉。
3. 学科分类区：五宫格学科快捷入口。
4. 学习进度卡：最近学习记录与继续按钮。
5. 课程列表区：同步精讲课程卡片。
6. 悬浮兑换按钮：固定于右下方，突出运营入口。

#### 设计要求

- 首页必须支持单手操作，高频点击区域集中在下半屏与中屏。
- 搜索框保持强可见性，作为课程查找主入口。
- 继续学习卡优先级高于课程列表。
- 悬浮兑换按钮不得遮挡底部导航主点击区域。

### 4.2 专题课页面

#### 页面目标

- 服务于“专题提分”场景。
- 通过专题标签和卡片方式增强课程的阶段性、方法论和专题感。

#### 页面结构

1. 页面标题与副标题。
2. 横向滚动筛选标签。
3. 专题课程卡片列表。

#### 设计要求

- 标签栏支持横向滑动，默认选中“全部专题”。
- 专题卡要明显区别于普通课程卡，强化“专题价值感”和“提分感”。
- 卡片中必须同时展示专题归属、课时数量、学习人数和动作按钮。

### 4.3 学习库页面

#### 页面目标

- 聚合用户学习资产。
- 帮助用户快速回到未完成学习内容。

#### 页面结构

1. 页面标题。
2. 四个资产入口：历史、下载、收藏、笔记。
3. 继续学习列表。

#### 设计要求

- 资产入口使用统一图标容器样式。
- 继续学习卡突出进度条，弱化营销信息。
- 学习库整体应保持“工具页”特征，视觉比首页更克制。

### 4.4 我的页面

#### 页面目标

- 承接账号与权益信息。
- 提供 VIP 兑换、账号设置和帮助入口。

#### 页面结构

1. 用户信息头图区域。
2. VIP 激活码兑换卡。
3. 功能菜单组。
4. 退出登录按钮。

#### 设计要求

- 个人信息区需要具备身份感与层次感，但不能压过兑换入口。
- VIP 兑换卡是页面第一优先级运营模块。
- 菜单列表应遵循统一行高、对齐与反馈规则。

## 5. 视觉设计系统

### 5.1 品牌气质

整体视觉采用“学习蓝 + VIP 金”的双主色策略：

- 蓝色承担学习、导航、操作、进度等功能属性。
- 金色承担会员权益、活动、兑换等运营属性。
- 背景以浅灰和白色为主，确保内容层级清晰、阅读负担低。

- 红点、角标、收藏等状态图标应具备显式状态色。

## 7. 交互与动效规范

### 7.1 交互原则

- 所有主操作必须具备即时反馈。
- 卡片类组件默认整卡可点，避免多重热点竞争。
- 点击反馈优先使用透明度变化、轻缩放或阴影变化，不使用复杂动画。

### 7.2 动效建议

| 场景 | 动效建议 |
| --- | --- |
| Tab 切换 | 内容直接切换，避免复杂场景转场 |
| 按钮点击 | 95% 到 98% 的轻微缩放 |
| 播放器上滑 | `500ms ease-in-out` |
| 弹窗出现 | `400ms` 弹性曲线入场 |
| Toast 消失 | `500ms` 透明度淡出 |

### 7.3 反馈状态

关键组件至少需要定义以下状态：

- 默认态
- 按下态
- 加载态
- 成功态
- 失败态
- 禁用态

当前原型已体现的状态：

- 课程封面骨架加载
- 兑换成功 Toast
- 页面级激活态 Tab

当前原型未体现但正式版必须补齐的状态：

- 搜索无结果
- 激活码错误或过期
- 网络异常
- 课程为空
- 学习库空状态

## 8. 适配与可用性规范

### 8.1 设备适配

- 设计基准建议采用 `375 x 812` 画板。
- 必须兼容刘海屏与底部手势区。
- 页面顶部和底部需要分别适配 `safe-area-inset-top` 与 `safe-area-inset-bottom`。
- 页面采用移动端纵向布局，禁止出现横向滚动，筛选标签栏除外。

### 8.2 可点击区域

- 主要点击目标不得小于 `44 x 44px`。
- 图标若承担独立操作，必须补足点击热区，不可只按视觉尺寸计算。

### 8.3 文本与可读性

- 正文字号不低于 12px。
- 重要按钮文字不低于 12px，且字重不低于 600。
- 灰色辅助文本必须保证与背景有足够对比度。

### 8.4 可访问性

正式版本建议补充以下规则：

- 输入框、按钮、弹窗需具备语义化标签。
- 图标按钮需要 `aria-label` 或等效说明。
- 不应全局禁用文本选择，至少在输入、课程详情、笔记区域允许复制。
- Toast 不应是唯一反馈方式，错误信息需在原位置明确展示。

## 11. 后台管理系统设计

### 11.1 设计目标

后台管理系统用于支撑前端移动端的课程分发、用户运营、会员权益和系统配置，不以复杂 ERP 为目标，而是围绕首版 MVP 提供稳定可运营的管理能力。

首版后台必须满足以下目标：

- 支撑前端同步课、专题课、学习库和个人页的数据配置与内容分发。
- 支撑用户查询、会员状态管理、激活码发放与核销追踪。
- 支撑课程内容、章节结构、讲义资源和封面素材的统一管理。
- 支撑多存储驱动切换与资源上传。
- 明确首版范围边界：不接第三方支付，不做在线充值，只支持激活码会员体系。

### 11.2 后台角色与权限建议

| 课程运营 | 课程内容维护、章节管理、资源上传 | 课程管理、资源管理、课程上下架 |
| 用户运营 | 用户查询、账号状态处理、学习数据查看 | 用户管理只读/部分编辑、会员信息查看 |
| 会员运营/客服 | 激活码生成、会员补发、兑换异常处理 | 会员管理、激活码批次、兑换记录、人工补偿 |

#### 首版范围边界

- 不接微信支付、支付宝、Apple IAP 等第三方充值。

- 激活码默认一人一次，不可重复使用。
- 已使用激活码不得再次分配给其他用户。
- 激活码支持批量生成、导出、作废。
- 激活成功后必须写入兑换记录和会员权益变更记录。

- 永久 VIP 套餐激活后，后续普通时长卡默认不再叠加，可由运营人工处理例外情况。

### 11.8 存储系统设计

#### 目标

系统需要支持统一上传接口，并在后台配置中切换不同存储驱动。首版要求支持以下 4 种方式：

1. 本地存储
2. S3 存储桶
3. 腾讯云对象存储
4. FTP 存储

#### 统一存储抽象建议

所有上传文件统一落一张资源表，避免上层业务直接依赖具体驱动。资源表建议包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `asset_id` | 资源 ID |
| `provider` | `local` / `s3` / `tencent_cos` / `ftp` |
| `bucket_or_root` | 存储桶或根目录 |
| `object_key` | 文件相对路径 |
| `origin_name` | 原始文件名 |
| `mime_type` | 文件类型 |
| `size` | 文件大小 |
| `etag_or_hash` | 哈希值或 ETag |
| `public_url` | 对外访问地址 |
| `created_at` | 上传时间 |

#### 驱动配置建议

| 存储类型 | 必填配置 |
| --- | --- |
| 本地存储 | 根目录、访问域名、是否公开读 |
| S3 存储桶 | Endpoint、Region、Bucket、Access Key、Secret Key、访问域名 |
| 腾讯云对象存储 | Bucket、Region、SecretId、SecretKey、访问域名 |
| FTP 存储 | Host、Port、Username、Password、根目录、被动模式、SSL 开关 |

#### 存储策略规则

- 同一时刻只允许一个“默认上传驱动”处于启用状态。
- 已上传资源必须保留资源元数据，不因默认驱动切换而失效。
- 课程视频、封面、讲义、头像均通过统一资源服务管理。
- 上传失败必须返回明确错误原因，后台需保留失败日志。
- 如果使用腾讯云对象存储，落地实现建议明确使用 COS SDK；文档层统一视作腾讯云对象存储驱动。

## 12. 核心业务规则补充

### 12.1 前后端权限联动

- 前端课程卡的 `FREE` / `VIP` 展示必须由后台课程权限字段统一控制。
- 用户会员有效期变化后，前端权限应在下次接口拉取时立即生效。
- 学习库中的下载资料权限必须与会员状态保持一致。

### 12.2 会员权益规则

- 首版会员权益默认为“全站 VIP 课程可学”，不做课程单买。
- 会员到期后，用户账号保留，但 VIP 权限失效。
- 激活码兑换成功必须支持幂等校验，避免重复提交造成多次加时。
- 人工补偿操作必须记录操作人、操作原因和变更前后值。

### 12.3 课程发布规则

- 课程封面、标题、课程权限、至少一个课时，是发布前必填条件。
- 下架课程前端不可新进入，但已学习记录仍保留。
- 讲义资源如果被替换，建议保留历史版本号，避免已下载记录失真。

### 12.4 存储与资源规则

- 所有上传资源都要通过后台统一校验扩展名、大小和 MIME 类型。
- 视频、图片、文档建议按业务目录分桶，例如 `courses/videos`、`courses/covers`、`courses/handouts`。
- FTP 仅作为兼容方案，正式大规模视频分发优先建议对象存储。
- 若后期接入 CDN，必须通过资源表中的访问域名统一透出。

### 12.5 审计与安全规则

- 后台所有新增、编辑、删除、作废、会员补偿操作必须写入操作日志。
- 激活码明文导出应限制为高权限角色。
- 存储密钥类配置应加密存储，前端后台页面仅展示脱敏值。

### 13.3 阶段任务拆解

#### M1：需求冻结与技术方案

- 明确课程模型、会员模型、激活码规则、存储策略。
- 冻结前端页面清单与后台菜单清单。
- 输出接口命名规范、状态码规范、资源上传规则。

#### M2：基础框架与权限骨架

- 完成后台登录态、路由、菜单、角色权限控制。
- 搭建系统设置页与统一表单规范。
- 搭建资源上传服务与资源表。

#### M3：课程与存储能力完成

- 完成课程列表、课程编辑、章节管理、资源上传。
- 实现本地、S3、腾讯云对象存储、FTP 四种驱动。
- 完成课程上下架与前台课程接口联通。

#### M4：用户与会员闭环完成

- 完成用户列表、详情、学习记录查询。
- 完成会员套餐、激活码批次、激活码状态管理。
- 打通前台兑换弹窗与后台激活码校验逻辑。

#### M5：联调测试与上线准备

- 核心流程回归：找课、开课、继续学习、兑换 VIP、权限生效。
- 补齐错误态、空状态、权限校验和失败提示。
- 录入首批课程与专题测试数据，准备上线。

### 13.4 进度跟踪设计

项目执行阶段建议使用统一进度状态，避免“开发完成但不可上线”的假完成：

| 状态 | 定义 |
| --- | --- |
| 未开始 | 任务未进入执行 |
| 进行中 | 已开始开发或设计 |
| 阻塞中 | 存在依赖未解决 |
| 待评审 | 开发完成，等待联调/验收 |
| 已完成 | 已通过验收标准 |

每个里程碑建议同步跟踪 5 类指标：

- 范围完成度
- 核心接口完成度
- 联调通过率
- P1/P2 缺陷数
- 初始化数据准备度

### 13.5 上线前必查清单

- 激活码生成、兑换、顺延、过期逻辑全部验证通过。
- VIP 与 FREE 课程权限在前端展示一致。
- 4 种存储驱动至少完成一次真实上传验证。
- 课程封面、视频、讲义都能正确回显与访问。
- 后台高权限页面和密钥配置已完成权限隔离与脱敏。
